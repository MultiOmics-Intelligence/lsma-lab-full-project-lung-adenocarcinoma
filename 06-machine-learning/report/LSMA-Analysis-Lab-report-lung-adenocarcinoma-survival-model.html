Methods

Assembled from what each completed stage recorded. Check it against the parameter tables below before using it in a write-up.

A model was trained to predict time to the event ('vital_status' = Dead; 200 patients, 82 events) from 17,485 features (gene expression, log2(counts per million + 1)). Restriction: none.

50 patients were set aside as a test set. On the remaining 150 (61 events), a Cox regression with elastic-net penalty (lifelines), on the features most related to survival in the training patients (univariate Cox score test, redone inside every fold) was fitted on 50 features; the penalty (0.02) was chosen by 5-fold on the training patients (concordance index 0.6251 +/- 0.1056).

On the test set the concordance index was 0.6431 (0.50 to 0.78 (95%, bootstrap)); predicted high- and low-risk patients were compared with the log-rank test (p = 0.04272). The model was validated on a held-out part of the same dataset; a second, independent cohort is the stronger test and is not available here.

Feature importance: weights of the penalised Cox model.

Random seed: 42. Software: python 3.12.16; joblib 1.6.0; lifelines 0.30.3; numpy 2.5.4; pandas 2.3.3; scikit-learn 1.9.1; scipy 1.18.1.

Analyses were run on the LSMA Analysis Lab (workflow 'machine-learning' version 1.0.0).

Features and outcome Exploratory

Machine learning needs a table with one row per sample and one column per feature (the expression of a gene, the methylation of a CpG, whether a gene is mutated), and an outcome for every sample. This stage builds the table from the dataset and takes the outcome from a column of the sample sheet that you choose. It then checks whether the data can support a model at all. With the task 'prediction' it builds the table the way the earlier model expects it: the same transformation, every gene kept, the model's features in its order, and features this dataset lacks filled with their training means. It reports how many are missing and refuses when more than 30% of the features the model uses are absent.

Note. There are 17,485 features for 200 samples. With far more features than samples a model can always find a pattern that fits the training data by chance; only the held-out test set shows whether it is real.

Stage 2 of 4

Training and model choice Statistically supported

A quarter of the samples are put aside as the test set and not touched. On the rest, each model is trained and scored several times by cross-validation: the training samples are cut into five parts, the model learns from four and is scored on the fifth, in turn. Choosing features, scaling them and tuning the model's settings are all repeated inside every round. The best model is then fitted on all training samples. Finally the labels are shuffled a hundred times and everything is repeated, to see what score pure chance produces. A survival model chooses its genes by their link to survival in the training patients of each fold (or by variance, if you ask). With the task 'prediction' nothing is trained: the stage only describes the earlier model that will be applied.

Note. Cross-validation chose the weakest penalty tried (0.02). A weaker one might have scored better still.

How to interpret this stage

Compare the test score with the cross-validation score: a much lower test score means overfitting. Look at the interval rather than the single number; with 20 test samples it is wide. Sensitivity and specificity depend on the threshold of 0.5, which is a convention; the ROC curve shows every threshold. In an external test, a score well below the source run's cross-validation is common and honest: it shows how far the model carries to other hospitals, platforms or populations.
